## 01. 先把这些名词放在正确的位置

你正在读的是一篇端到端语音识别（ASR）论文：输入是声音，输出是文字。**WeNet** 是完成数据处理、模型训练、识别和工业级部署的工具包；**U2** 是论文在这个工具包里实现的「统一流式与非流式的两遍识别方案」。

| 所处层次 | 名称 | 它负责回答什么 |
| :--- | :--- | :--- |
| **任务** | 语音识别（ASR） | 怎样把声音信号转成文字序列 |
| **工具项目** | WeNet | 怎样准备数据、训练、识别与工业部署 |
| **整体方案** | U2 | 怎样用两遍识别，在单一模型上统一流式与非流式 |
| **功能模块** | 共享编码器、CTC 部分、Attention 解码器 | 模型内部各部分分别负责什么职责 |
| **网络结构** | LSTM、Transformer、Conformer | 用怎样的计算结构实现上述功能模块 |
| **内部组成** | 层（Layer）、模块和参数 | 怎样逐层计算，训练时调整哪些权重数值 |

- **编码器和解码器是“分工名称”**：编码器负责整理输入声学信息；解码器负责据此预测文字输出。LSTM 可以用于编码器或解码器；Conformer 在 Transformer 自注意力的基础上加入卷积，进一步捕捉相邻语音帧的局部特征。

## 02. 从声音到 Fbank 再到编码器表示

神经网络处理的是数字。先把连续声音按时间切成很短、彼此重叠的片段，每个片段叫一**帧（frame）**。论文使用 $25\text{ ms}$ 的窗口，每隔 $10\text{ ms}$ 取一帧，再计算 $80$ 维 log-Mel Fbank 特征：

$$\text{声音波形} \longrightarrow \text{Fbank } (T \times 80) \longrightarrow \text{编码器表示 } \mathbf{H}\,(T' \times D)$$

- **一段语音对应一个矩阵**：如果有 $T$ 帧，每帧 $80$ 个数，Fbank 就是 $T \times 80$ 的矩阵（$1$ 秒语音约 $100$ 帧）。
- **下采样与深层表征**：编码器先做 $4$ 倍卷积下采样，再逐层加工，维度从 $T \times 80 \to T' \times D$（其中 $T' \approx T/4$，常用配置 $D = 256$）。

| 表示 | 每一行对应什么 | 数字主要描述什么 |
| :--- | :--- | :--- |
| **Fbank** | 一个 $25\text{ ms}$ 声音时间片 | 各频段的对数能量等声学线索 |
| **编码器表示 $\mathbf{H}$** | 一个下采样后的声音位置（约 $40\text{ ms}$） | 结合上下文、对识别有用的声学内部特征 |
| **文字 token 嵌入** | 一个文字 token（汉字或特殊符号） | 网络学习到的文字向量，供解码器使用 |

## 03. 编码器与两个解码支路怎样合作

U2 的核心架构由**一个共享编码器（Shared Encoder）**和**两个解码模块（CTC Decoder + Attention Decoder）**组成：

| 部分 | 接收什么 | 产生什么 |
| :--- | :--- | :--- |
| **共享编码器** | Fbank 声音特征 | 带上下文的声音向量序列 $\mathbf{H}$ |
| **CTC 输出部分** | 声音向量 $\mathbf{H}$ | 每个时间位置的文字及 `blank` 概率 |
| **Attention 解码器** | $\mathbf{H}$ 和已给出的文字 token | 下一个 token 的概率；或整条候选句得分 |

## 04. 核心：把论文 Figure 1 展开成两遍识别流程

```text
                [ 共享编码器 (Transformer / Conformer) ]
                     输出一串带上下文的声学向量 H
                        │                     │
          ┌─────────────┘                     │ (声音信息 H)
          ▼                                   │
 [ 第一遍：CTC 输出与前缀束搜索 ]               │
   边接收语音，边维护 N-best 候选               │
          │                                   │
          ▼                                   ▼
 [ 候选文字列表 (Hypotheses) ] ───► [ 第二遍：Attention 解码器 ]
   · 今天的天起很好                     读取 H 和候选文字，重新评分
   · 今天的天气很好                               │
                                                  ▼
                                      [ 综合打分选出最终文字 ]
                                        示例：今天的天气很好
```

1. **第一遍（First Pass）**：CTC 把声音向量 $\mathbf{H}$ 转成逐帧概率，再通过**前缀束搜索（Prefix Beam Search）**维护若干高分候选文字（`N-best hypotheses`）。在流式模式下，可以在语音不断到达时实时给出阶段性识别结果。
2. **第二遍（Second Pass / Rescoring）**：在句子结束后，Attention 解码器同时读取声音向量 $\mathbf{H}$ 和这 $N$ 条候选文字，通过 Teacher Forcing 并行计算每条候选的 Attention 得分，再与 CTC 得分加权选出最终结果：
   $$S_{\text{final}} = \lambda\,S_{\text{CTC}} + (1 - \lambda)\,S_{\text{Attention}}$$

> ⚠️ **注意**：“重打分”是在已有候选中重新排序选择。若正确文字完全没进入第一遍的候选列表，单靠重打分流程一般无法凭空补出正确句子。

## 05. CTC 与 Attention 各解决什么问题？

一段声音可能有几百帧，而对应文字只有十几个字，且没有逐帧对齐标注。**CTC** 通过引入空白符 `blank`（记作 `_`）和“**先合并相邻重复、再删除 blank**”的折叠规则，解决帧与文字长度不同、边界未知的单调对齐问题：

| 逐帧路径示例 | 第一步：先合并相邻重复 | 第二步：再删除 `blank` |
| :--- | :--- | :--- |
| `你 你 _ 好 好` | `你 _ 好` | **你好** |
| `哈 _ 哈` | `哈 _ 哈` | **哈哈**（中间隔了 `blank`，保留两个“哈”） |
| `哈 哈` | `哈` | **哈** |

- **CTC 的优势与短板**：单调对齐可靠，不跳读、不漏读，天然适合流式第一遍；但各时间步输出条件独立，缺乏文字上下文语言建模能力。
- **Attention 的互补作用**：Attention 解码器既参考声学表征 $\mathbf{H}$，又参考已生成的历史文字上下文，因此能给整条候选句更完整的语言通顺度评分。

## 06. 流式和非流式怎样通过「动态分块」统一？

- **非流式（Non-streaming）**：等整句语音到齐后再识别，注意力可以看整句的前后文（`full` 模式）。
- **流式（Streaming）**：语音边到达边处理。通过**分块注意力（Chunk-based Attention）**，让当前块（如第 2 块）只能查看**当前块内部**和**所有历史块**（第 1 块），不能查看尚未到达的未来块（第 3、4 块）。
- **动态分块训练（Dynamic Chunk Training）**：训练时不固定一种 chunk 大小，而是在每个批次随机采样不同大小的块（如 $\text{chunk} \in \{16, 8, 4, \text{full}\}$）。这样训练出的**同一套模型参数**，在推理时选小块就能做低延迟流式识别，选 `full` 就能做高准确率非流式识别！

## 07. 联合训练损失 vs 两遍识别

训练阶段有正确答案，模型同时优化 CTC 与 Attention 两个分支的加权损失（原文公式 1）：

$$\mathcal{L}_{\text{joint}} = \lambda\,\mathcal{L}_{\text{CTC}} + (1 - \lambda)\,\mathcal{L}_{\text{AED}}$$

常用配置中 $\lambda = 0.3$（即 `ctc_weight = 0.3`）。请区分：**“联合训练”**指训练阶段用两个损失共同更新编码器；**“两遍识别”**指推理阶段先由 CTC 产生候选、再由 Attention 重打分。

## 08. 读实验表时盯住哪几个指标？

节选原论文 Table 1（AISHELL-1 测试集 CER%，越低越好）：

| 解码方法 | M1 (full 专训) | M2 (`full`) | M2 (`chunk=16`) | M2 (`chunk=8`) | M2 (`chunk=4`) |
| :--- | :---: | :---: | :---: | :---: | :---: |
| Attention 单独解码 | 5.69 | 6.04 | 6.35 | 6.45 | 6.70 |
| CTC 前缀束搜索 | 5.91 | 6.28 | 6.98 | 7.40 | 7.89 |
| **Attention 重打分** | **5.30** | **5.52** | **6.05** | **6.28** | **6.62** |

- **纵向对比同一列**：Attention 重打分比单独用 CTC 或单独用 Attention 错误率都更低。
- **横向对比 M2 行**：推理块越小，延迟越低，但可用上下文减少，CER 略有上升——直观体现了**准确率与等待时间的权衡**。
- **RTF（Real-Time Factor，实时率）**：$\text{RTF} = \text{计算耗时} \div \text{音频时长}$（例如处理 $10\text{ s}$ 音频耗时 $1\text{ s}$，则 $\text{RTF} = 0.1$）。注意：块越小虽然等待音频收齐的延迟（Latency）越短，但由于神经网络调用次数变多，总计算开销（RTF）反而可能增大。

## 09. 十道自测题检验理解

1. **WeNet、U2、Conformer 分别处在哪一层？**
   > 工具包、整体两遍识别方案、可用于编码器的网络结构。
2. **为什么 Fbank 不是图里的文字词嵌入？**
   > Fbank 每行对应一个声音时间片；文字嵌入每行对应一个文字 token。
3. **编码器输出的 $\mathbf{H}$ 已经是汉字了吗？**
   > 不是，仍是一串带上下文的内部实数向量，后面经过线性分类层和搜索解码才变成文字。
4. **两个解码部分为什么叫“共享编码器”？**
   > CTC 分支和 Attention 解码器使用同一份声音编码结果 $\mathbf{H}$。
5. **第二遍 Attention 只看 CTC 的文字吗？**
   > 不是，它同时看候选文字与声音向量 $\mathbf{H}$，再给每条候选评分。
6. **正确句子如果不在第一遍候选中，重打分能直接补出来吗？**
   > 不能，纯重打分只在已有 $N$ 个候选里重新排序。
7. **流式分块下，当前块能看哪些声音？**
   > 所有历史块和当前块整块；不能看未来块。
8. **动态分块统一了什么？**
   > 训练时随机改变块大小，使同一套模型参数同时支持小块流式识别和 `full` 非流式识别。
9. **小块一定让总计算时间更快吗？**
   > 不一定。首字等待延迟更短，但分块调用次数增加，整体 RTF 可能更大。
10. **U2 的“两遍识别”和“联合训练”分别指什么？**
    > 推理识别时先出候选再重打分；训练时同时优化 $\mathcal{L}_{\text{CTC}}$ 和 $\mathcal{L}_{\text{AED}}$。
