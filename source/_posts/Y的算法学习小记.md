我（Yhc）学习了一段时间编程算法，在这里和想学算法的朋友分享一些经验（自己走了些弯路）。

- **小白题单**：https://vjudge.net/article/11277
- **Codeforces**：https://codeforces.com/contests
- **AtCoder**：https://atcoder.jp/

以上三个网站都是很好的国内外算法练习网站，对梯子没有硬性要求，小白题单对已经基本掌握 C 或 C++ 的朋友可以开始接触并完成。

<!-- more -->

在此处特地强调：**要在算法领域深入研究首推 C++！** 根据以往的数据，参加算法竞赛的平均 1500 多支队伍里有 1300 多支队伍使用 C++，其余使用 Java 或 Python，几乎没有人使用 C 语言。

并不是说 C 语言不好（我一开始也是学习 C 语言），而是每种语言都有自己的特点，C 语言更注重极致的效率，大部分工作需要程序员自己完成；而 C++ 虽然在效率上略逊于 C，但 C++ 的 STL 库中有许多的常用工具及容器，因此我们选择舍弃一小部分性能换取对参赛选手的减负（实际上程序效率主要看选手实力而不是编程语言）。

我了解大家基本大一要学编程的话基本也都是学习 C 语言，但 C++ 编译器基本是兼容所有 C 语法的，大家可以放心学 C，学好 C 后再学 C++ 是添砖加瓦而非推倒重来。

首先，在网站上打比赛的前提是你基本已经大致掌握一门编程语言（最好是 C++，C 也可以），打比赛时自备翻译系统（除非你能看懂全英文的题干，或者你精通日语）。

接下来为大家介绍下面两个网站：这两个网站是世界上最著名的两个编程算法爱好者的聚集地，每周都会不定时地举行比赛供全世界的编程算法爱好者们练手。**Codeforces**（下面简称 CF）的比赛分四个级别（Div. 1, Div. 2, Div. 3, Div. 4），数字越小难度越高，初学者建议打 Div. 4，有一定基础和自信的可以打 Div. 3。在这里提前告诉大家：这里面的题目都不简单，就算你打最低级的 Div. 4 两个小时七道题只写出来一半不到也不用灰心（别问我怎么知道，以前被干破防了）。

**AtCoder** 里的比赛建议大家打 Beginner Contest，和 CF（不是穿越火线）里的 Div. 3、4 差不多，相对 CF 而言 AtCoder 的界面更友好（但是日本网站）。

在这里再说些我个人感觉蛮重要的，很多人认为算法就是研究高深的计算逻辑、复杂巧妙的数据结构。我告诉你：这些确实重要，但重要的远不止这些！**细节决定成败**真的太对了，细节习惯有问题可能让你给代码查错一下午都找不出问题在哪，所以我在这里列出我个人认为小白容易出错的点：

1. **数组下标越界**，导致访问未知内存
2. **循环变量设置错误**，导致死循环
3. **变量忘记初始化**，导致输出随机值
4. **时间复杂度把握不当**

第四点小白可能没有接触，我讲讲自己的理解。我们都认为电脑就是用来做重复机械化计算的，确实如此！但这并不代表你可以浪费电脑的算力。对于新手而言，最常见的滥用算力导致时间复杂度爆表的例子就是滥用循环，动辄就嵌套两到三层的循环，写出平方级 $\mathcal{O}(n^2)$ 甚至立方级 $\mathcal{O}(n^3)$ 的代码。我们假设题目所给的数据量一般是 $2 \times 10^5$（`2e5`，二乘十的五次方），那嵌套两层计算机就要进行 $4 \times 10^{10}$（`4e10`）次计算，三层就是 $8 \times 10^{15}$（`8e15`）次计算。正常情况下每秒评测机（跑你代码给你打分的电脑）只能跑 $10^8$（`1e8`）组数据（题目的时间限制一般是两秒），所以显然不行（除非你能搞到神威·太湖之光做你的评测机）。这就是算法的重要性，起到用最小的算力跑出结果的作用！
